# Scenario checks

Rehearse these cases without changing a real submission. Record which checks were
actually exercised; structural validation and reading this table do not establish
browser behavior or a successful publication.

| Request or condition | Expected decision |
| --- | --- |
| Publish Spur with a required local CLI and no remote service | Inspect its prerequisites and current eligibility route; no invented MCP server. |
| Publish knowledge-kit with an authenticated remote service | Use its own identity, privacy facts, reviewer access, and real MCP tests. |
| Chrome's `/json/version` fails and `DevToolsActivePort` is protected | Discover the authorized live endpoint; no automatic Full Disk Access request. |
| Policy returns 200 locally, portal warns, GPTBot returns 403 | Separate observations from hypotheses; preserve protections and unresolved warning. |
| User says legal boxes are checked and submission is complete | Read back review and publication states; do not report approval from submission. |
| Update a version already in review | Inspect replacement effects and cancellation authorization before uploading. |
| Approved version: user asks to publish | Confirm version and availability, perform authorized publication, verify saved state. |
| Uploaded draft: user asks whether others can discover it | Verify publication and listing evidence; draft upload or local installation is insufficient. |
