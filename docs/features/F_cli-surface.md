# F: CLI Surface

## Goal
The `superskill` binary's command surface (apps/cli): Commander wiring for install, skill/agent/command/hook/magent lifecycle verbs (scaffold/validate/evaluate/refine/evolve), script path/run, and hook run — plus argv parsing, stdin handling, exit codes, help text, and the testable-output contract. Everything an operator can type, and nothing they can't.
## Scope
- In: apps/cli/** (commands, argv, stdin, hooks dispatch, templates); command/flag/env-var shapes (synced to 04_DESIGN same-commit); exit-code conventions; `--json` machine output; the script/hook dispatcher family deep-import exception (ADR-022/024).
- Out: domain logic and no-app operation APIs (→ G Package Core); plugin-side hook scripts and guard engines (→ H Plugin CC); marketplace plugin content (→ I).
## Acceptance Criteria
Feature: CLI Surface

  Scenario: Every CLI command is wired through Commander in apps/cli and documented in 04_DESIGN.
    Given a new or changed CLI command, flag, or environment variable
    When it lands
    Then apps/cli wires it via Commander and docs/04_DESIGN.md carries its shape in the same commit

  Scenario: CLI stdout output remains testable via process.stdout.write.
    Given any command that emits primary output
    When tests assert on that output
    Then they spy on process.stdout.write without coupling to log formatting
