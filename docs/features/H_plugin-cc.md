# H: Plugin CC

## Goal
The bundled Claude Code plugin (plugins/cc): skills, commands, agents, hooks, rules, scripts, plugin.json, and its tests — the distributable unit every target install consumes. This area owns plugin content, executable hook/guard contracts, and distributed documentation integrity, with H1 (portable script staging) and H2 (security/contract integrity) as its active workstreams.
## Scope
- In: plugins/cc/** (skills, commands, agents, hooks, rules, scripts, tests); hook invocation contracts and guard engines; distributed Markdown integrity; install-time staging of plugin scripts (H1); security and contract drift (H2).
- Out: CLI/core mechanics that serve all plugins (→ F/G); other bundled or third-party plugins; repo tooling (→ E); top-level skills/ distribution copies (→ I).
## Acceptance Criteria
Feature: Plugin CC

  Scenario: The cc plugin installs cleanly to every declared target.
    Given the bundled plugins/cc tree
    When superskill install runs for any declared target
    Then skills, commands, agents, hooks, and rules land in that target's canonical locations

  Scenario: Contract regressions fail the plugin's own test suite.
    Given a change to plugins/cc hooks, scripts, or distributed docs
    When a protected contract regresses
    Then the relevant plugins/cc test fails — parity with H2's integrity scenarios
