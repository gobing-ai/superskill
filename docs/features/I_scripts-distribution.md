# I: Scripts & Distribution

## Goal
Cross-module scripts and distribution artifacts: top-level skills/ distribution directories, vendors/ reference-only upstream copies, release mechanics (standalone binary build, npm publishing), and marketplace registration assets. Narrow by operator ruling: cc plugin's own scripts live in H, build tooling lives in E — this area holds only what no single module owns.
## Scope
- In: skills/ top-level distribution artifacts; vendors/ (reference-only, never locally edited); release/publish pipeline (bun run build, npm packaging); marketplace registration assets; cross-module scripts owned by no single package.
- Out: plugins/cc/scripts (→ H Plugin CC); build/test tooling configs (→ E Project Foundation); domain code (→ G); CLI surface (→ F).
## Acceptance Criteria
Feature: Scripts and Distribution

  Scenario: skills/ distribution artifacts track their plugin sources.
    Given a skill shipped both under plugins/cc/skills and top-level skills/
    When one side changes
    Then the distribution copy is regenerated or the divergence is explicitly documented

  Scenario: vendors/ stays reference-only.
    Given any proposed change under vendors/
    When it is reviewed
    Then it is a wholesale upstream sync — never a local modification
